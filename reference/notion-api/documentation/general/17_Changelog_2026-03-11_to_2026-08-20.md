# Changelog: 2026-03-11 through 2026-08-20

> Source: https://developers.notion.com/page/changelog
> Fetched: 2026-08-22

Continues from `12_Upgrade_Guide_2026-03-11.md`, which covers only the
`2026-03-11` API version release itself. This file vendors every changelog
entry from that release through the most recent entry at fetch time
(2026-08-20). Two entries are called out specifically in issue #60 as
mattering most for this refresh: **June 29** (async page markdown writes)
and **August 7** (`notion-fetch` truncation metadata, the source of
`unknown_block_count`) — both are expanded further in `14_Page_Markdown.md`
and `15_Async_Tasks.md`.

Entries are listed newest first, matching the live changelog's own order.

## August 20, 2026 — Notion Agent APIs in public beta

The Notion Agent APIs moved from private alpha to public beta: starting chat
sessions with Custom Agents, streaming replies, submitting actions, and
paginating session event history. New: querying agents, per-agent usage
insights, and managing agents programmatically (credit limits, enable/
disable). Adds asynchronous batch operations for agent management. Replaces
threads/messages-shaped endpoints with JSON-body session/event endpoints;
migration deadline September 30, 2026. Out of scope for this client (no
agent surface exists here).

## August 13, 2026 — MCP view tooling, multi-source SQL

- `notion-create-view`/`notion-update-view` MCP tools gained relation,
  person, status, created-by, last-edited-by, unique-ID, last-visited,
  verification, and place filters; verification filters round-trip through
  view responses both ways.
- New tool-list responses drop `notion-query-database-view`;
  `notion-query-data-sources` with `mode: "view"` replaces it.
- Multi-source SQL via `notion-query-data-sources` now works on Business
  plans with Notion AI (previously Enterprise-only).
- `@notionhq/client` v5.25.1 fixes `isFullDataSource`/`isFullDatabase` type
  guards; v5.25.2 adds `does_not_equal` to verification property filters.

MCP-tool-scoped; no REST surface change for this client.

## August 12, 2026 — Formula properties, `filter_properties` on page writes

- **Update a data source** now stores `prop("Property Name")` references
  exactly as written (previously silently rewritten); invalid expressions
  now return `validation_error`. Formula properties created via the API
  preserve their result type.
- **Retrieve a data source** gradually returns formula expressions using
  `prop()` syntax instead of internal property references (see
  `FormulaConfiguration.usesInternalReferences()` in this client).
- **Create a page / Update page properties** now accept `filter_properties`,
  matching Retrieve a page. See `13_Filter_Properties.md`.
- Admin API reference now covers agent-management endpoints (credit usage,
  limits, permissions, status, creation policy, workflow metadata) — out of
  scope for this client.

## August 10, 2026 — Query tool reorganization

`notion-query-data-sources` now handles both SQL queries and saved database
views via `mode: "view"` + `view_url`. MCP-scoped.

## August 7, 2026 — Truncation metadata on `notion-fetch`

The `notion-fetch` MCP tool's response gained `truncated`,
`unknown_block_ids`, and `unknown_block_count` for large pages that can't
fully load. `unknown_block_ids` lists up to 50 omitted subtree root IDs;
`unknown_block_count` is the total omitted-root count. Callers pass IDs back
into `notion-fetch` to retrieve specific subtrees. This changelog entry
frames the feature as an MCP `notion-fetch` change specifically — the REST
`GET /v1/pages/{id}/markdown` endpoint's own reference page (fetched
directly for `14_Page_Markdown.md`) independently confirms the same three
fields on the REST response, so the REST shape is not solely inferred from
this MCP-framed entry, contrary to what issue #60 assumed going in.

## August 5, 2026 — `unsupported` formula/rollup values

Formula and rollup page-property values can come back with `type` set to
`"unsupported"` when the value depends on too many related pages or nested
formulas; the response omits the partial value. `@notionhq/client` v5.24.0
adds `client.blocks.meetingNotes.create()`, typed `unsupported` values, and
`APIErrorCode.InvalidBeta`. This client already models `unsupported` for
both `FormulaResult` and `RollupResult` (see `FOLLOWUPS.md` items 12/13/33).

## August 3, 2026 — MCP protocol version

Notion MCP's Streamable HTTP endpoint supports MCP protocol version
2026-07-28, staying backward compatible with 2025-era versions. MCP-scoped.

## July 27, 2026 — Tool access naming, `notion://docs/*`

`current_tool_access` status `limited_free_trial` renamed to
`available_with_limit` (no functional change). `notion-fetch` now accepts
`notion://docs/*` URIs. MCP-scoped.

## July 17, 2026 — `current_tool_access` map

`notion-fetch`'s `self` response gained a `current_tool_access` map (plan +
tool availability per tool: `available`, `available_with_limit`,
`upgrade_required` with `upgrade_url`, or `not_enabled`). MCP-scoped.

## July 15, 2026 — OAuth fields, `notion.so` → `notion.com` links, trash filters

- User objects gained `email_verified`; MCP token responses gained
  `user_id`, `workspace_id`, `email_domain`.
- **App links moved from `notion.so` to `notion.com`.** Generated `url`
  values for pages/databases/data sources now point to
  `https://app.notion.com/p/{page-id}`. These are human-facing links, not
  stable identifiers — use `id`. (Relevant to issue #60 item 17's link
  sweep, and to `QUICKSTART.md`'s existing "Legacy URL" callout, which
  already documents this move.)
- **Search** gained `filter.in_trash` to list trashed pages/data sources.
  **Query a data source** gained an `is_archived` body parameter to query
  archived pages instead of live ones. `@notionhq/client` v5.23.2 adds
  `filter.in_trash` to `client.search()`.

## July 14, 2026 — Longer MCP token lifetime

Notion MCP access tokens last ~8 hours (up from 1). MCP-scoped.

## July 8, 2026 — Webhook signature helper, large data source iteration, async page writes, 529 retries

- `@notionhq/client` v5.23.0 adds `verifyWebhookSignature()` and
  `signWebhookPayload()` (testing). See `18_Webhooks_Reference.md`.
- New `iterateAllDataSourceRows()`/`collectAllDataSourceRows()` SDK helpers
  page past the 10,000-row limit via windowing, de-duplicating rows.
  Vendored as prior art at `reference/js/pagination-helpers.ts` (issue #60
  item 27; see that directory's README).
- `notion.asyncTasks.retrieve({ task_id })` adds typed async-task support;
  page-create and markdown-update methods accept `allow_async: true`. See
  `15_Async_Tasks.md` and `14_Page_Markdown.md`.
- The SDK now auto-retries HTTP 529 (`service_overload`), respecting
  `Retry-After`.

## July 3, 2026 — HTML blocks

HTML blocks can now be created via the API: upload a `.html` file via the
File Upload API, attach via `embed.file_upload` when appending block
children, creating pages, or updating blocks. No block type currently
modeled for this in `Block.kt`/`BlockRequest.kt` — worth a follow-up if
HTML-block support is wanted.

## July 2, 2026 — PAT expiration options

Developer portal PAT expiration choices: 7/30/90/180 days or 1 year
(default). Workspace admins can view/revoke PATs. Not API-surface relevant.

## July 1, 2026 — Icon naming, database icons

Native icon `name` accepts icon-picker names (e.g. `"token"`, `"star
circle"`). `databases.retrieve` now returns icons matching
`dataSources.retrieve`.

## June 29, 2026 — Async page markdown writes

Create-page and update-page-markdown endpoints accept `"allow_async": true`;
Notion returns an `async_task` handle with `status_url` and
`poll_after_seconds`. Notion MCP supports the async flow through
`notion-create-pages`, `notion-update-page`, `notion-get-async-task`. This
is the changelog entry issue #60 called out specifically — fully vendored in
`14_Page_Markdown.md` and `15_Async_Tasks.md`, and already implemented in
this client (`PagesApi.createFromMarkdownAsync`/`createAsync`,
`AsyncTasksApi`, `MarkdownApi`).

## June 25, 2026 — Workspace identity via `notion-fetch`

`notion-fetch` accepts the special id `self`, returning workspace/user
identity without a separate REST call. MCP-scoped.

## June 22, 2026 — AI assistant DB access, status option groups

- Business-plan teams with Notion AI can query single databases/views
  directly from AI assistants (previously Enterprise-only). MCP/product
  feature, not API-surface relevant.
- **Status option groups**: status options accept an optional `group` field
  on create/update, assigning `To-do`/`In progress`/`Complete`. See
  `16_Status_Option_Groups.md`.

## June 16, 2026 — Workspace-level rate limits

Per-workspace rate limits now apply in addition to per-connection limits,
scaled to plan; `Retry-After` still governs 429 backoff.

## June 10, 2026 — Bots in people properties

Bots (as user objects) can be assigned to `people` page properties and
referenced in `user` rich-text mentions.

## June 8, 2026 — Unique OAuth tokens per authorization

New public-connection OAuth authorizations mint fresh token pairs instead of
reusing an existing active token.

## May 15, 2026 — Markdown insertion positions

`insert_content.position` on the update-page-markdown endpoint supports
prepend (page start) / append (page end) without a full-page rewrite. See
`14_Page_Markdown.md`.

## May 12, 2026 — Developer portal, PATs

New Developer portal at `https://www.notion.so/developers`. Personal access
tokens can be scoped to Notion API access, Workers access, or both.

## May 11, 2026 — Query meeting notes, agent parent type

New `POST /v1/blocks/meeting_notes/query` endpoint. Pages/blocks parented by
agents now serialize `parent` as `{"type": "agent_id", "agent_id": "..."}`.

## April 22, 2026 — Pagination reliability

Data source query pagination cursors embed session identifiers, eliminating
intermittent `validation_error`s from overlapping pagination sessions.

## April 20, 2026 — 10,000-row pagination cap

Query a data source, Create a view query, and Get view query results now
enforce a max pagination depth of 10,000 results, surfaced via
`request_status: {type: "incomplete", incomplete_reason:
"query_result_limit_reached"}`. This is the limit `DataSourcesApi.iterateAllRows`
/ `ViewsApi.iterateAllRows` work around (see `FOLLOWUPS.md` items 25/26/28
and `reference/js/pagination-helpers.ts`).

## April 17, 2026 — Comment update/delete GA, multi-value filters

Update/Delete comment endpoints are GA (non-DLP integrations can only touch
comments they created). Database/data source filters accept arrays for
`equals`/`does_not_equal` (select, status) and `contains`/`does_not_contain`
(multi_select).

## April 7, 2026 — Comment markdown

Create comment accepts an optional `markdown` string as an alternative to
`rich_text` (exactly one required).

## March 30, 2026 — `heading_4`, tab-item icons, relative filters

`heading_4` block type supported. Tab-child paragraph blocks support
`icon`. People filters accept `"me"`. Date filters accept relative values
(`today`, `tomorrow`, `yesterday`, `one_week_ago`, `one_week_from_now`,
`one_month_ago`, `one_month_from_now`).

## March 25, 2026 — Tab blocks, writable verification, native icons

Tab blocks (`type: "tab"`, paragraph children). Wiki-database `verification`
property writable via Create/Update page. Native icons use structured
`type: "icon"` with `name`/`color`. New `GET /v1/custom_emojis`.

## March 19, 2026 — Views API launch, status property support

Eight endpoints for programmatic view management (create/retrieve/update/
delete, list, query). Status properties creatable/updatable on Create/Update
database via `{status: {}}`, with custom initial options.

## March 11, 2026 — API version `2026-03-11`

Covered fully in `12_Upgrade_Guide_2026-03-11.md` — `after` → `position`,
`archived` → `in_trash`, `transcription` → `meeting_notes`.
